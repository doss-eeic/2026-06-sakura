# ローカル画像リンクのプレビュー（Phase 2 実装）

## 使い方

- 「編集」→「挿入」→「画像リンクを挿入...」でPNG/JPEGを1枚選ぶ。
- または、PNG/JPEGを編集領域へ左ドラッグ＆ドロップする。複数画像は落とした位置に文書の改行コードで区切って挿入される。
- リンク上に約500msマウスを置くと画像を表示する。手入力・貼り付けしたリンクも、文書の拡張子によらず対象になる。
- 本文にはリンク文字列だけが入り、通常のUndo/Redoが使える。元画像のコピー・移動や本文の事前保存は不要。

```text
図の説明: ![図](C:/Pictures/図.png)
空白や括弧を含むパス: ![図 (1)](<C:/My Pictures/図 (1).jpg>)
```

手入力の `C:\Pictures\図.png` も認識する。対象はドライブ文字を持つローカル絶対パスの `.png` / `.jpg` / `.jpeg`。
相対パス、UNC、HTTP(S)、通常リンク、裸のパスはプレビューしない。

既存のカスタムメニューに項目が出ない場合、メニュー設定の機能一覧「挿入」から「画像リンクを挿入...」（機能コード30796）を追加できる。

## 実装の要点

- `sakura_core/util/ImageLink.*`: リンク生成・論理行内のリンク区間解析・ファイル検証。
- `sakura_core/view/CEditView_ImageLink.cpp`: ドロップの一括判定、座標変換、ホバー待機。
- `sakura_core/window/CImagePreviewWnd.*`: 非アクティブな表示専用ポップアップとWICワーカー。
- メニューからは通常選択を置換する。左ドロップは選択を解除して落とした位置へ挿入する。矩形選択・編集禁止時には挿入しない。
- 非画像・ディレクトリ混在のドロップは従来のファイルオープンへ渡す。右ドラッグで明示的に選ぶ「開く」も従来どおり。OLEと`WM_DROPFILES`で同じ画像挿入判定を使う。
- ホバー位置のレイアウト行から論理行へ変換する。折り返しインデント、行末以降、改行記号はホバー対象にしない。
- WICでコンテナーがPNG/JPEGであることと、各辺8192px以下・総画素数2000万以下であることを確認してから画素をデコードする。元画像の32bit画素換算は最大約80MB。UIスレッドではデコードしない。
- 表示サイズは最大480×360論理ピクセル相当、原寸より拡大しない。モニターの作業領域とウィンドウDPIを考慮する。
- キャンセル時は世代番号を更新し、遅れて完了したデコード結果を破棄する。失敗時のダイアログや自動再試行はない。別リンクへの移動や再ホバーで再度読み込む。

## ビルド・検証記録

2026-10-15、Windows / MSVC、x64 Debugで検証。

通常のビルド:

```bat
build-sln.bat x64 Debug
```

今回、既存の `x64\Debug\sakura.exe` が起動中でリンク時にロックされていたため、同じソリューションを別出力先でビルドした。
Visual Studioの開発者コマンドプロンプトでは、リポジトリルートから次のように再現できる。

```bat
msbuild sakura.sln /p:Platform=x64 /p:Configuration=Debug /p:OutDir=%CD%\build\phase2-check\ /t:Build
```

検証用実行ファイルは `build/phase2-check/sakura.exe`。
言語DLL・既存の外部ツール/DLLも検証用フォルダに配置してテストした。

テスト（検証用フォルダを作業ディレクトリにして実行）:

```bat
tests1.exe --gtest_filter="ImageLink.*:ImagePreview.*:ImagePreviewFile.*:ImageLinkEditor.*:CShareDataTest.InitShareData001"
tests1.exe --gtest_output=xml:phase2-tests.xml
```

- 新規16件＋既定メニュー初期化1件: **17件成功**。
- 全体: **1647件中1637件成功、10件失敗**（無効化済み28件は別）。結果は `build/phase2-check/phase2-tests.xml`。
- 残る失敗:
  - `CSakuraEnvironmentTest.ExpandParameter_mixed`: Documents配下のパスが「マイドキュメント」表記へ変換され、絶対パスを期待するテストと不一致。
  - `FontFallback.DrawingAndMeasurementUseSameFontNumber` と `CharWidthCache` の8件: `DLLSHAREDATA is not initialized`。これらだけの実行でも再現する既存テストの初期化問題。
- 実エディタを別プロファイルで起動したスモークテスト: 手入力PNGリンクのホバー表示、非アクティブ表示、リンクから離れた際の非表示、再ホバーでの復帰、編集時の非表示、キー操作だけで再表示しないことを確認。

## 追加の手動受け入れ確認

以下の実操作の組み合わせは、自動テスト・上記スモークテストに加えて確認する。

1. 未保存の文書で日本語・空白・`]`・丸括弧を含む画像名を選び、リンクと元ファイルを確認する。選択範囲の置換、キャンセル、Undo/Redoを試す。
2. エクスプローラーから画像1件／複数件を行の途中や別ペインへ落とす。非画像混在、ディレクトリ混在、右ドラッグの3つのメニュー、OLE設定OFF時も確認する。
3. ビューモード、読み取り専用による編集禁止、矩形選択では画像リンクが入らないことを確認する。
4. 文中の複数リンク、タブ・全角文字の後のリンク、画面幅で折り返されたリンクで、文字のない領域に反応しないことを確認する。
5. 画像表示中／500msの待機中／デコード中に、スクロール、ペイン切替、文書の再読込、ウィンドウ非アクティブ化を行う。古い画像が再表示されないことを確認する。
6. 画像を移動・削除して再ホバーする。破損画像・上限超過画像の後に正常画像へ移動し、正常に表示できることを確認する。
7. 辞書Tip、URL操作、範囲選択、補完、ミニマップと併用する。複数モニター・異なるDPI・画面四隅でもポップアップが作業領域内に収まることを確認する。
